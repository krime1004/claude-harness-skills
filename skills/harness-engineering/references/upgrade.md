# 하네스 업그레이드 — 버전별 변경 항목

업그레이드 모드(SKILL.md "업그레이드 모드")가 이 문서를 쓴다. 프로젝트 `CLAUDE.md`의 `<!-- harness-engineering vN -->` 다음 버전부터 현재 버전까지의 항목을 차례로 반영한다. 표시가 없으면 v1이다.

현재 버전: **v3**

## 반영 원칙

- **확인 먼저.** 항목마다 "반영 확인" 명령이나 기준으로 이미 있는지 본다. 있으면 건너뛰고, 일부만 있으면 빠진 부분만 채운다.
- **프로젝트 사정을 따른다.** 예시 경로와 이름은 프로젝트의 실제 언어·구조에 맞춘다. 맞지 않는 항목(예: 실행할 표면이 없는 라이브러리의 검증 스킬)은 건너뛰고, 이유를 `docs/tech-debt/` 또는 최종 보고에 남긴다.
- **항목마다 커밋 하나.** 프로젝트 검사를 통과시킨 뒤 커밋한다. push는 하지 않는다.
- **이력을 읽어야 하는 항목은 따로 승인받는다.** 표에서 "무거움"으로 표시한 항목이다.
- **기존 기록은 고쳐 쓰지 않는다.** 결정 로그, lineage, history처럼 추가만 하는 문서는 앞으로의 줄만 새 형식을 따른다.

## v2 → v3 (2026-11-09)

웹 앱 기본 규칙(`webapp-remote-access.md`)을 반영한다. **웹 앱이거나 웹 앱 예정인 프로젝트만 대상이다.** 아니면 3-1~3-14를 모두 건너뛰고 이유를 최종 보고에 남긴 뒤 3-15만 한다. 표의 "절"은 `webapp-remote-access.md`의 절 번호다.

이 버전의 항목은 한꺼번에 반영하지 않는다(`webapp-remote-access.md` 머리말 "적용 범위"). 남은 항목 목록을 보여 줄 때 아래 두 가지를 함께 알린다.
- 포트(3-2)나 기본 경로(3-3)가 바뀌면 사용자가 할 일이 생긴다: 구글 OAuth redirect URI 재등록, 기존 `tailscale serve` 설정을 해제하고 공개 스크립트로 다시 등록하기.
- 3-5·3-6·3-8은 보안 경계 변경이다(0-2절). 사용자가 승인한 계획이 있을 때만 진행한다.

2. 위와 같은 표로 `## vN-1 → vN (날짜)` 절을 추가한다. 항목마다 반영 확인 방법과 적용 방법을 적는다.
3. "현재 버전", SKILL.md Phase 1의 버전 표시 설명, `checklist.md` Phase 1 템플릿의 버전 표시를 함께 바꾼다.
4. SKILL.md 변경 이력에 남긴다.
