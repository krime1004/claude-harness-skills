# Phase 3 — 반복 실수를 저장소 구조로 막기

에이전트가 같은 실수를 반복하면, 다음 프롬프트가 아니라 저장소를 고친다. 이 문서는 Phase 3(암묵적 규칙을 기계적 규칙으로 전환)의 상세 절차다.

출처: cursor/plugins의 pstack `skills/correct/SKILL.md`(`/correct`)를 이 스킬 구조에 맞게 옮겼다.

## 전제 — 기여자는 모두 에이전트라고 가정한다

에이전트는 자기가 연 파일만 보고, 가장 가까운 예시를 복사하고, 컴파일되는 가장 짧은 길을 택한다. 그래서 파일 하나만 보고 맞아 보이는 변경이 저장소 전체에서도 맞도록 설계한다.

## 1. 실수 유형 찾기

다음을 읽고 실수를 유형별로 묶는다.

- 최근 커밋과 revert
- PR/리뷰 코멘트
- 에이전트 지침 파일(`CLAUDE.md`, `AGENTS.md`)의 산문 규칙
- 우회 이유를 설명하는 코드 주석
- 사용자가 세션에서 반복해서 고친 지시

**같은 유형이 두 번 나오면 규칙 후보다.** 한 번 나온 것은 일화로 보고 넘긴다.

## 2. 가장 높은 수준에서 고치기

위에서부터 시도하고, 안 되는 경우에만 아래로 내려간다.

| 순서 | 수준 | 방법 |
| --- | --- | --- |
| 1 | 아키텍처로 없애기 | 상태마다 주인을 하나로, 작업마다 지원하는 방법을 하나로 둔다. 내부를 숨겨 잘못된 import가 실패하게 한다. 손으로 맞추는 목록은 단일 원본으로 바꾼다. 에이전트가 복사할 만한 옛 방식과 죽은 코드를 지운다. |
| 2 | 타입으로 막기 | 잘못된 상태를 아예 쓸 수 없게 한다. |
| 3 | 린트·CI·훅으로 막기 | 잘못된 코드가 여전히 컴파일되면 검사를 추가한다. 에러 메시지에 대신 쓸 파일·타입·함수를 적는다. |
| 4 | 테스트로 잡기 | 동작이 깨져도 통과하는 테스트, 내부만 바뀌어도 실패하는 테스트는 고치거나 지운다. |
| 5 | 문서·에이전트 규칙 | 판단이 필요한 경우에만 쓴다. 에이전트가 건너뛰어도 아무것도 실패하지 않으므로 마지막이다. |

사람의 코드 리뷰는 이 표에 없다. 리뷰어가 PR마다 같은 실수를 잡아야 한다면 그것이 이 절차로 고칠 문제다.

문서 수준(5)에 머물 수밖에 없다면 지시를 더 눈에 띄는 곳에 두고, 실패 사례 예시를 함께 적는다.

## 3. 고치고 증명하기

- **자주 나온 유형부터, 유형 하나에 커밋 하나.**
- **새 검사가 과거의 실제 실수에서 실패하는지 확인한다.** 그 실수가 있던 커밋이나 같은 코드를 임시로 되살려 검사를 돌리고, 실패 출력을 확인한다. 한 번도 실패해 본 적 없는 검사는 증명되지 않은 검사다.
- **같은 명령을 로컬과 CI(또는 pre-commit)에서 돌린다.** 로컬에서만 도는 검사는 우회된다.
- **위반이 이미 많으면 늘어난 것만 실패시킨다(점진 강제).** 현재 위반 수나 목록을 기준 파일로 저장하고, 기준보다 늘면 실패하게 한다. 기존 위반을 고치면 기준을 줄인다.
- **예외는 위반한 줄에 적는다.** 사유, 만료일, 승인한 사람을 함께 적는다. 예: `# rule-exempt: no-direct-db (사유: 마이그레이션 스크립트, 만료 2026-12-31, 승인: <사람>)`. 예외 표기 형식도 검사로 강제할 수 있다.

## 4. 규칙·강제수단 대응표 유지

`CLAUDE.md`(길면 `docs/`로 옮기고 링크)에 아래 표를 둔다.

```markdown
## 규칙과 강제수단

| 규칙 | 강제수단 | 실패를 증명한 사례 |
| --- | --- | --- |
| service/는 ui/를 import하지 않는다 | `tests/architecture/test_layer_boundaries.py` | 커밋 abc1234의 revert |
| 판단이 필요한 규칙 예: 공개 API 이름은 도메인 용어를 쓴다 | 없음(문서) | — |
```

- 사용자가 실수를 지적하면, 고치는 것과 함께 표에 규칙을 추가한다.
- **표에 이미 있는데 강제수단이 "없음"인 규칙이 다시 지적되면 반복 사례다.** 같은 변경 안에서 한 수준 이상 올려서 고친다.
- 실수가 구조적으로 불가능해진 규칙은 표에서 뺀다.

## 보고 형식

유형마다 근거(커밋, 코멘트 위치), 고른 수준, 더 높은 수준을 쓰지 못한 이유를 적는다.
